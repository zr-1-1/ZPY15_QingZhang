## 2. 高优先级：真近点角恒为 0

### 2.1 错误原因

第 111～113 行先计算近地点幅角 `w`：

```matlab
sinw = e_vector(3)/(e*sin(i));
cosw = (e_vector(1)*cos(omega)+e_vector(2)*sin(omega))/e;
w = atan2(sinw, cosw);
```

第 116～118 行又计算完全相同的两个表达式，然后减去 `w`：

```matlab
sin_theta_w = e_vector(3)/(e*sin(i));
cos_theta_w = (e_vector(1)*cos(omega)+e_vector(2)*sin(omega))/e;
theta = atan2(sin_theta_w, cos_theta_w) - w;
```

因此，只要中间计算为有限实数，就有 `theta = w - w = 0`。偏心率矢量指向近地点，不能在这里替代当前的位置矢量。

对正常椭圆轨道，`a > 0`、`0 < e < 1`，继而有：

```text
sin_phi = 0
cos_phi = e + norm(r)/a > 0
phi = 0
M = 0
```

这会把碎片放到各自轨道的近地点，丢失实际历元上的轨道相位。轨道大小和空间朝向仍可能看起来正常，因此只检查 a、e、i 或结果是否有限不能发现此错误。

| 偏心率范围 | 0.00328065990082～0.366311008169 |
| 倾角范围 | 1.71045385951～1.74538661583 rad |
| 独立计算的 M 范围，归一化到 [0, 2π) | 0.0117470995976～6.2621801131 rad |

例如 Debris1：原函数 `M = 0`，独立结果 `M = 3.62180971437933 rad`，原结果回代位置误差约 15,718,296.78 m。

独立相位计算使用能量求 a，再由位置、径向运动直接计算偏近点角，避开被检查的真近点角表达式：

```matlab
rnorm = norm(r);
a_ref = -mu / (2*(dot(v,v)/2 - mu/rnorm));
e_ref = norm(cross(v,cross(r,v))/mu - r/rnorm);
sinE = dot(r,v)/(e_ref*sqrt(mu*a_ref));
cosE = (1-rnorm/a_ref)/e_ref;
E_ref = atan2(sinE, cosE);
M_ref = mod(E_ref-e_ref*sin(E_ref), 2*pi);
```

以上公式用于非圆椭圆验证，不是对圆轨道的通用处理。回代使用仓库当前的 `orb_elements2rv.m`，不是第三方独立轨道软件；它与独立相位公式及代码恒等式共同支持本结论。

### 2.3 修正方向

对 `e > 0`、`norm(h) > 0` 的非退化轨道，可以直接用位置和偏心率矢量的有向夹角求真近点角：

```matlab
cos_theta = dot(e_vector,r)/(e*norm(r));
sin_theta = dot(cross(e_vector,r),h)/(e*norm(r)*norm(h));
theta = atan2(sin_theta,cos_theta);
```

或者延续原代码意图，先由**位置矢量**求纬度幅角 u，再令 `theta = u-w`：

```matlab
sin_u = r(3)/(norm(r)*sin(i));
cos_u = (r(1)*cos(omega)+r(2)*sin(omega))/norm(r);
theta = atan2(sin_u,cos_u)-w;
```

后一方案仍要求非赤道轨道。两种片段都必须结合适用域及退化分支，不能直接视为完整修复。

第 119 行 `cos_phi = (e*a+norm(r)*cos(theta))/a` **本身不是独立的公式错误**：对一致的椭圆状态，利用 `r/a = (1-e^2)/(1+e*cos(theta))`，它等价于 `(e+cos(theta))/(1+e*cos(theta))`。当前它的问题来自错误的 theta。第 120 行椭圆偏近点角正弦公式也成立。

## 3. 圆轨道和赤道轨道缺少退化处理

第 111 行分母为 `e*sin(i)`：圆轨道 `e=0` 时近地点方向无定义；赤道轨道 `i=0` 或 `i=π` 时升交点方向无定义。第 103 行在赤道轨道中即使返回某个数值，也不能将它视为唯一的物理升交点赤经。

以下是 MATLAB 原函数实测，采用归一化单位、`mu=1`，便于精确构造输入：

| 输入 | 输出 `[a,e,i,Omega,omega,M]` |
| --- | --- |
| 圆极轨道：`r=[1;0;0]`，`v=[0;0;1]` | `[1,0,π/2,0,NaN,NaN]` |
| 赤道椭圆：`r=[1;0;0]`，`v=[0;0.5;0]` | `[0.571428571429,0.75,0,0,NaN,NaN]` |

建议按偏心率与相对节线长度 `norm(cross([0;0;1],h))/norm(h)` 设置有说明的容差分支。圆倾斜轨道可约定近地点幅角为 0，并用纬度幅角保存相位；赤道椭圆可约定升交点赤经为 0，并保存近地点经度。圆赤道轨道应保存位置经度，逆行赤道轨道还须统一角度方向和回代约定。

NASA/JPL 的 `cspice_oscelt` 文档也说明圆轨道、赤道轨道的角度需采用约定，近圆、近赤道时经典根数可能不可靠。这是边界处理依据，并不意味着当前工程必须引入 SPICE。[参考文档](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/MATLAB/mice/cspice_oscelt.html)

## 4. 行向量输入不兼容

第 101 行：

```matlab
h_mo = sqrt(h' * h);
```

仅当 `h` 为 3×1 列向量时，这是角动量模长。若 `r`、`v` 为 1×3 行向量，则 `h'*h` 为 3×3 外积矩阵，后续计算发生维度错误。用 CSV 第一条状态的行向量调用，MATLAB 实测错误标识为 `MATLAB:dimagree`。

当前第 60 行通过列索引传入 3×1 向量，因此当前循环不触发该问题。函数注释只说“矢量”，未声明形状限制。

建议先验证输入为含三个实数有限元素的向量，再用 `r=r(:); v=v(:); h_mo=norm(h);` 统一形状。也可以明确只接受列向量并提供可理解的错误信息。

## 5. 无效状态和非椭圆输入未限制

函数未验证 `mu` 为正的有限实标量、`r` 和 `v` 为有效三维实向量、`norm(r)>0`、`norm(h)>0`，也没有声明只支持椭圆轨道。

- `r=0` 或 `mu<=0` 会导致除零或没有物理意义的结果。
- 径向运动 `cross(r,v)=0` 时轨道平面无定义。实测 `mu=1, r=[1;0;0], v=[1;0;0]` 返回 `[NaN,1,NaN,0,NaN,NaN]`。
- `e=1` 时第 115 行半长轴公式分母为 0，当前用有限 a 表示的接口不适用于抛物线。
- `e>1` 时第 120 行 `sqrt(1-e^2)` 不属于实数椭圆公式；双曲轨道应采用双曲偏近点角及相应的平近点角关系。由于当前 theta 为 0，某些输入会掩盖这个问题：实测 `mu=1, r=[1;0;0], v=[0;2;1]` 仍返回有限的 `[-1/3,4,0.463647609001,0,0,0]`。该样例处于近拱点，M 为 0 本身合理，但不代表该实现支持一般双曲轨道。

建议根据当前碎片任务明确限制为非退化椭圆状态，越界时给出明确错误；只有确有需求时再扩展其他圆锥曲线。

## 6. 数值稳定性与接口说明

以下是静态分析发现的风险，不能表述为当前 345 条 CSV 已出现的错误：

- 第 104 行直接 `acos(h(3)/h_mo)`，未保护浮点舍入造成的越界。可在有效状态检查后截断到 `[-1,1]`，或用 `atan2(norm(h(1:2)),h(3))` 计算倾角。
- 第 111 行在 `e` 很小或 `sin(i)` 很小时放大舍入误差。改用有向向量夹角可减少显式除以 `sin(i)` 的问题，但不能消除经典根数自身的圆轨道奇异性。
- 第 115 行在 `e≈1` 时的 `1-e^2` 存在消减与敏感性。能量公式也会在近抛物线状态下敏感，不能仅换一个公式就认为风险消失；应明确适用范围和阈值。
- 本函数变量 `omega` 实际是大写 Ω（升交点赤经），变量 `w` 才是小写 ω（近地点幅角）。返回顺序 `[a;e;i;omega;w;M]` **符合**工程 `[a,e,i,Omega,omega,M]` 的语义，没有发现两列交换；但命名容易引发维护错误。
- `atan2` 返回的 Ω、ω 可以为负。负角度与相差 2π 的正角度在几何上等价，不能直接判为错误。建议明确初始根数是否统一到 `[0,2*pi)`，并与 `rv2coe` 的约定一致；传播函数的累计角度是另一种用途，不应无条件归一化。
- 注释应补充惯性参考系、`mu` 单位 m³/s²、输入形状、输出为 6×1、适用轨道类型及退化约定。没有证据表明当前输入坐标系或单位错误，因此不将其列为已确认故障。
